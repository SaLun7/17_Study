# 02. K-Fold 교차검증

[← DAY1 목차](<README.md>) · [원본 노트북](<02_K-Fold 교차검증.ipynb>)

하나의 학습·검증 분할에 의존하지 않고 데이터를 여러 fold로 나누어 결정트리의 성능을 반복 평가한다.

## 핵심 개념

### K-Fold

전체 데이터를 K개 묶음으로 나누고 한 묶음씩 검증용으로 바꾸어 사용한다.

### 평균과 변동

평균은 대표 성능, 폴드 간 차이는 데이터 분할에 대한 민감도를 나타낸다.

### Stratified K-Fold

분류 문제에서는 각 fold의 클래스 비율을 유지하는 방식이 더 안전하다.

교차검증은 평가에 쓰는 표본을 번갈아 바꿔 한 번의 분할에 결과가 좌우되는 정도를 살펴보는 방법이다. 각 fold에서 전처리를 새로 학습해야 한다. 전체 데이터에서 먼저 스케일링하거나 결측값을 채운 뒤 fold를 나누면 검증 자료의 정보가 학습에 섞인다.

## 실습 흐름

전체 데이터를 여러 fold로 나누고 한 fold를 검증용으로 남겨 두면서 학습과 평가를 반복했다. 각 fold의 점수를 따로 기록한 뒤 평균과 변동 폭을 확인했다. 일반 K-Fold와 클래스 비율을 유지하는 Stratified K-Fold의 차이도 분류 문제의 관점에서 비교했다.

### 사용한 함수

| 함수·클래스 | 역할 |
|---|---|
| `load_iris` | Iris 데이터셋 불러오기 |
| `KFold` | K개의 교차검증 분할 생성 |
| `DecisionTreeClassifier` | 결정트리 분류 모델 |
| `accuracy_score` | 분류 정확도 계산 |

## 실행 결과

평균 정확도만 보지 말고 각 fold 점수의 범위도 확인한다. 점수 차이가 크다면 데이터가 작거나 클래스 분포가 불안정할 수 있다.

## 필요한 파일

Iris 데이터셋을 K개의 학습/검증 폴드로 순환 분할

데이터를 불러오는 셀부터 실행한다. 별도의 로컬 입력 파일을 지정하지 않는다.

## 다시 볼 것

- 분류에서는 각 fold의 클래스 비율이 지나치게 달라지지 않는지 확인한다.
- 전처리도 각 학습 fold 안에서 학습해야 검증 데이터 정보가 새지 않는다.
- 평균 점수만 보지 말고 fold별 차이가 큰지도 함께 기록한다.
