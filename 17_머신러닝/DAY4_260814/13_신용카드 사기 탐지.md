# 13. 신용카드 사기 탐지

극심한 클래스 불균형을 가진 거래 데이터에서 로지스틱 회귀와 LightGBM을 비교하고 스케일링과 이상치 처리 효과를 확인한다.

## 실습 내용

- 사기 비율을 유지해 데이터를 분할한다.
- 정확도·정밀도·재현율·F1·AUC를 함께 평가한다.
- Amount를 스케일링하고 이상치를 점검한다.
- 선형 모델과 부스팅 모델을 비교한다.

**데이터**  
Credit Card Fraud: 익명 PCA 피처, Amount, Time, 사기 여부 Class

## 핵심 메모

### 불균형 착시

정상 거래만 예측해도 정확도가 매우 높게 나올 수 있다.

### 재현율

실제 사기를 얼마나 놓치지 않고 찾았는지 나타낸다.

### 이상치

사기 신호일 수도 있으므로 업무 의미 없이 무조건 제거하면 안 된다.

```python
from sklearn.metrics import confusion_matrix, accuracy_score, precision_score, recall_score, f1_score
from sklearn.metrics import roc_auc_score

def get_clf_eval(y_test, pred=None, pred_proba=None):
    confusion = confusion_matrix( y_test, pred)
    accuracy = accuracy_score(y_test , pred)
    precision = precision_score(y_test , pred)
    recall = recall_score(y_test , pred)
    f1 = f1_score(y_test,pred)

    roc_auc = roc_auc_score(y_test, pred_proba)
    print('오차 행렬')
    print(confusion)

    print('정확도: {0:.4f}, 정밀도: {1:.4f}, 재현율: {2:.4f},\
    F1: {3:.4f}, AUC:{4:.4f}'.format(accuracy, precision, recall, f1, roc_auc))
```

## 실습 흐름

사기 비율을 유지해 데이터를 분할하고 로지스틱 회귀와 LightGBM으로 기준 결과를 만들었다. 거래 금액을 표준화하거나 로그 변환한 뒤 결과가 어떻게 달라지는지 비교했고, 주요 피처의 이상치를 제거한 실험도 따로 진행했다. 각 단계마다 혼동행렬과 정밀도, 재현율, F1, AUC를 같은 함수로 계산했다.

## 결과 메모

기본 로지스틱 회귀의 높은 정확도는 사기 탐지 성능 전체를 의미하지 않는다. 정밀도·재현율·F1·AUC를 함께 보고 오류 비용에 맞는 임계값을 선택한다.

## 사용한 함수

| 함수·클래스 | 역할 |
|---|---|
| `read_csv` | CSV 파일을 DataFrame으로 읽기 |

| `StandardScaler` | 평균 0, 표준편차 1로 표준화 |
| `LogisticRegression` | 확률 기반 선형 분류 모델 |
| `LGBMClassifier` | LightGBM 분류 모델 |
| `accuracy_score` | 분류 정확도 계산 |
| `confusion_matrix` | TN·FP·FN·TP 혼동행렬 계산 |
| `precision_score` | 정밀도 계산 |
| `recall_score` | 재현율 계산 |
| `f1_score` | 정밀도와 재현율의 조화평균 계산 |
| `roc_auc_score` | 확률 순위 기반 ROC-AUC 계산 |

## 다시 볼 것

- 이상 거래가 적기 때문에 99% 이상의 정확도도 충분한 결과가 아닐 수 있다.
- 이상치는 오류가 아니라 사기의 중요한 신호일 수도 있다.
- 실제 운영에서는 사기 누락 비용과 정상 거래 차단 비용으로 임계값을 정한다.

## 정리

- stratify를 사용해 양성 비율을 유지한다.
- 재표본화는 분할 이후 학습 fold 안에서 수행한다.
- 정상 차단과 사기 누락의 비용을 분리한다.
