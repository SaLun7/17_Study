# 02. 감정 분류 튜닝과 RAG 이미지 생성

[← DAY2 목차](<README.md>) · [원본 노트북](<02_감정 분류 튜닝과 RAG 이미지 생성.ipynb>)

임베딩 기초를 복습한 뒤 감정 분류 미세조정, 로컬 대화 모델, 문서 검색 기반 답변, 이미지 생성으로 이어진다. 여러 작업을 한 노트북에서 연결한 실습이다.

## 핵심 개념

전체 미세조정은 모델의 많은 가중치를 바꾸고, 이 예제의 prompt tuning은 본체를 고정한 채 가상 토큰과 분류층을 학습한다. 사람이 입력하는 문장 prompt와 학습 가능한 벡터 prompt는 다르다.

RAG는 지식을 가중치에 다시 학습시키는 대신 관련 문서를 검색해 질문과 함께 모델에 전달한다. 문서를 나누는 크기, 겹치는 구간, 임베딩 방식, 검색 결과 수가 답변에 영향을 준다. 출처가 붙어 있어도 답변이 그 출처를 정확히 반영하는지는 확인해야 한다.

RAG 답변이 틀렸을 때는 먼저 검색된 조각을 읽는다. 관련 조각이 없으면 분할·임베딩·검색 단계의 문제를 살펴보고, 근거가 있는데 답변이 어긋나면 전달한 문맥과 생성 지시를 확인한다. 문서 조각을 너무 작게 만들면 맥락을 잃고 너무 크게 만들면 불필요한 내용이 함께 들어온다. 검색 결과 수를 늘리는 것만으로 답변이 좋아지지는 않는다.

## 실습 흐름

NSMC로 전체 미세조정과 prompt tuning을 비교한다. Ollama의 Gemma로 대화 기록·스트리밍·JSON 응답을 확인한 뒤 동아리 문서를 조각내 Chroma에 저장한다. 유사 문서를 찾아 답변에 사용하고, 마지막에는 한국어 요청을 이미지용 prompt로 바꿔 Stable Diffusion으로 그린다.

## 실행 결과

QUICK 설정의 저장 출력에서 분류 정확도는 미세조정 전 46.8%, 후 77.4%이고 prompt tuning은 75.4%다. QUICK은 학습 2,000개·평가 500개를 사용한다. 문서 5개에서 18개 조각을 만들어 384차원 벡터로 저장했다. 자료에 없는 질문에 모른다고 답하는 예제도 포함돼 있다.

## 필요한 파일

공용 `assets/puppy.jpg`와 `data/knowledge/`의 텍스트 5개가 포함돼 있다. Ollama와 `gemma3:4b`, 여러 Hugging Face 모델은 별도로 내려받는다. Chroma DB와 모델·이미지 출력은 해당 DAY의 `work/`에 생성한다.

## 다시 볼 것

검색된 문서가 질문에 맞는지 먼저 보고 생성 답변을 확인한다. 현재 색인 셀은 같은 이름의 Chroma collection을 지우고 다시 만들므로 수동으로 추가한 문서가 있다면 재실행 전에 따로 보관한다.
