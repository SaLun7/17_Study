# 12. T5 뉴스 요약

[← DAY4 목차](<README.md>) · [원본 노트북](<12_T5 뉴스 요약.ipynb>)

뉴스 기사 앞에 작업 지시를 붙여 T5로 짧은 요약을 생성했다. 입력과 출력이 모두 텍스트인 text-to-text 방식의 예제다.

## 핵심 개념

T5는 `summarize:` 같은 접두어로 수행할 작업을 표현한다. 기사는 인코더 입력, 요약은 디코더의 학습 대상으로 사용한다. 길이가 다른 요약을 묶을 때 padding 위치를 손실에서 제외해야 빈 토큰을 맞히는 데 학습이 치우치지 않는다.

학습 손실이 낮아지는 것과 요약이 중요한 내용을 빠짐없이 담는 것은 같지 않다. 생성 문장이 자연스러워도 원문에 없는 내용을 덧붙였는지 따로 읽어 봐야 한다.

요약 정답은 기사 문장을 그대로 줄인 것만은 아니어서 입력과 출력 길이가 서로 다르다. 생성 시 최대 길이를 너무 짧게 잡으면 핵심 문장이 중간에 끊길 수 있고, 길게 잡으면 반복이 늘 수 있다. 기사·참조 요약·생성 요약을 나란히 읽으며 주체, 숫자, 사건의 관계가 유지되는지 본다. 참조 문장과 표현이 다르다는 이유만으로 곧바로 틀린 요약은 아니다.

## 실습 흐름

`argilla/news-summary`에서 기사·요약 쌍을 준비하고 T5 토크나이저로 인코딩한다. `t5-small`을 학습하며 검증 손실이 개선될 때 가중치를 저장하고, 마지막에 생성 요약과 참조 요약을 나란히 출력한다.

## 실행 결과

저장 출력에서는 5 epoch 동안 검증 손실이 약 3.332에서 2.614로 내려갔다. 요약 예시도 남아 있지만 별도의 ROUGE 점수는 없다. 앞쪽 `inspect.getsource(train)` 셀은 뒤에서 정의하는 함수를 참조하므로 새 커널에서는 그 확인 셀을 건너뛰거나 함수 정의 뒤에 실행해야 한다.

## 필요한 파일

데이터와 `t5-small`을 내려받는다. `models/T5ForConditionalGeneration.pt`는 학습 중 만드는 결과 파일이며 저장소에 포함하지 않는다.

## 다시 볼 것

디코더 입력과 정답을 한 칸 옮기는 방식, 시작 토큰, padding 처리의 관계를 다시 본다. 저장된 출력은 이전 실행 기록이며 셀 순서대로 새로 실행한 검증과는 구분한다.
