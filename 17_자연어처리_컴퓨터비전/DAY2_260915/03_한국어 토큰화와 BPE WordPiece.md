# 03. 한국어 토큰화와 BPE WordPiece

[← DAY2 목차](<README.md>) · [원본 노트북](<03_한국어 토큰화와 BPE WordPiece.ipynb>)

공백·문자·자모·형태소 단위로 문장을 나눠 보고, 말뭉치에서 subword 토크나이저를 직접 학습했다.

## 핵심 개념

어떤 단위로 문장을 자르는지는 어휘 크기와 미등록 단어 처리에 영향을 준다. 한국어는 조사와 어미가 붙기 때문에 공백 분리만으로는 같은 어근이 서로 다른 단어가 되기 쉽다. 형태소 분석은 언어 단위로 나누고, subword 토큰화는 더 작은 조각을 조합해 새로운 단어도 표현한다.

BPE는 자주 나타나는 조각을 합쳐 어휘를 만든다. WordPiece도 subword 어휘를 사용하지만 같은 문장이 같은 조각으로 나뉜다고 가정하면 안 된다. 토큰 문자열, 토큰 ID, 복원된 문장을 따로 확인한다.

어휘를 크게 잡으면 자주 쓰는 표현을 짧은 토큰 시퀀스로 만들 수 있지만 모델의 임베딩 표도 커진다. 어휘가 작으면 낯선 단어를 더 작은 조각으로 표현하는 대신 시퀀스가 길어진다. 형태소 경계와 subword 경계가 일치하지 않는 이유도 서로 다른 기준으로 단위를 만들기 때문이다. 같은 예문으로 토큰 수와 실제 경계를 같이 비교한다.

## 실습 흐름

Okt·Kkma로 한국어를 분석하고 NLTK·spaCy의 영어 토큰화와 품사 분석을 비교한다. Korpora 말뭉치를 `corpus.txt`로 저장한 뒤 SentencePiece BPE와 WordPiece를 학습하고 encode·decode 결과를 확인한다.

## 실행 결과

저장된 실행 출력은 없다. 다만 과정의 `models` 폴더에는 `petition_bpe.model`, `petition_bpe.vocab`, `petition_wordpiece.json`이 포함돼 있어 저장된 토크나이저를 읽는 예제에 사용할 수 있다.

## 필요한 파일

`data/corpus.txt`는 앞의 말뭉치 수집 셀에서 만든다. KoNLPy에는 Java 환경이 필요하고, NLTK 자료와 spaCy 언어 모델도 준비해야 한다. 모델 파일 경로는 과정 루트를 기준으로 맞췄다.

## 다시 볼 것

토큰 ID는 토크나이저마다 의미가 다르므로 서로 바꿔 쓸 수 없다. 정규화·소문자화 설정이 원문 복원에 어떤 영향을 주는지도 확인한다.
