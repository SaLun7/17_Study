# 08. StoryBot DPO와 생성 평가

[← DAY4 목차](<README.md>) · [원본 노트북](<08_StoryBot DPO와 생성 평가.ipynb>)

StoryBot의 사전학습과 생성 결과를 확인한 뒤, 선호 응답과 비선호 응답의 쌍으로 DPO를 진행했다.

## 핵심 개념

DPO는 같은 prompt에 대한 chosen·rejected 응답을 비교한다. 기준 모델과 학습 모델이 두 응답에 부여한 로그 확률 차이를 사용해 선호 응답의 상대적 확률을 높인다. 별도의 보상 모델을 학습하는 단계는 이 코드에 없다.

생성 결과를 다른 언어 모델에게 평가하게 하는 방식은 빠르게 비교할 수 있지만 평가 prompt, 모델, 표본에 영향을 받는다. 사람 평가나 정답률과 같은 의미로 해석하지 않는다.

선호 쌍은 같은 질문에 대한 두 답이어야 비교 의미가 있다. DPO는 chosen의 확률만 따로 올리는 것이 아니라 rejected와의 상대 차이를 기준 모델에 비해 바꾸도록 학습한다. 선호 자료가 문법만 좋아하고 내용 일관성은 놓쳤다면 그 편향도 학습될 수 있다. 평가 승률을 읽을 때는 어떤 기준으로 선호를 정했고 같은 기준으로 평가했는지도 함께 본다.

## 실습 흐름

TinyStories 사전학습 후 여러 시점의 이야기를 생성하고 일관성·문법을 평가한다. DPO 데이터셋을 만들어 응답 부분의 로그 확률을 계산하고 학습한 뒤, 사전학습 모델과 DPO 모델의 이야기를 일대일로 비교한다.

## 실행 결과

저장 출력에는 DPO 1,000회 학습과 비교 100회의 결과가 있다. DPO 70승, 사전학습 29승, 무승부 1회로 무승부 제외 승률은 약 70.7%다. 이 평가 조건의 결과이며 이야기 생성 전반의 우위를 입증하는 수치는 아니다.

## 필요한 파일

모듈은 DAY3의 `storybot`을 공유한다. DAY4의 `storybot/`에는 별도의 train·valid 텍스트를 준비하며 그 폴더에 결과를 저장한다. DPO JSON은 DAY3에 포함된 파일을 참조한다. 외부 모델 평가 셀은 개인 `OPENAI_API_KEY` 설정과 API 사용 비용이 필요하다.

## 다시 볼 것

평가 셀은 외부 API에 생성된 이야기를 전송한다. 로컬 학습과 외부 평가를 구분해서 필요한 부분만 실행한다. DPO 이전·이후에 같은 prompt와 생성 설정으로 비교했는지 확인한다.
